# GreenCycle Database Overview

This document explains the current database design from `server/prisma/schema.prisma`.

## Database Stack

- ORM: Prisma Client
- Database: PostgreSQL
- ID strategy: UUID strings generated by Prisma with `@default(uuid())`
- Main timestamp patterns:
  - `createdAt` uses `@default(now())`
  - `updatedAt` uses `@updatedAt` where automatic update tracking is needed

Note: the datasource currently declares `provider = "postgresql"`, but the `url = env("DATABASE_URL")` line is commented out in the Prisma schema.

## Core Concepts

GreenCycle is modeled around household or enterprise recycling pickup requests.

The main flow is:

1. A user owns an `Account`.
2. The account can represent a `Customer`, `Driver`, or `RecyclingPartner`.
3. A customer stores one or more pickup `Address` records.
4. The customer creates a `PickupRequest`.
5. The request contains one or more `WasteItem` records, each linked to a `WasteCategory`.
6. Admin or operations staff can assign the request to a driver through `PickupAssignment`.
7. Assignments can be grouped into a `CollectionCluster` for route planning.
8. Pickup progress is tracked through `PickupTimeline`.
9. Completed recycling activity updates rewards, wallet transactions, and environmental impact records.

## Enums

### `UserRole`

Defines the account role:

- `CUSTOMER`
- `DRIVER`
- `ADMIN`
- `PARTNER_STAFF`

### `PickupStatus`

Tracks the full lifecycle of a pickup request:

- `PENDING`: waiting for admin approval
- `VERIFYING`: information is being verified
- `APPROVED`: approved and waiting to be clustered
- `ASSIGNED`: assigned to a driver and route
- `COLLECTING`: driver is on the way
- `ARRIVED`: driver has arrived
- `COLLECTED`: items have been collected
- `IN_TRANSIT`: items are being transported
- `AT_WAREHOUSE`: items reached the sorting warehouse
- `COMPLETED`: handed to recycling partner and points are completed
- `CANCELLED`: cancelled by customer
- `REJECTED`: rejected by admin
- `FAILED`: pickup failed
- `RESCHEDULED`: pickup was rescheduled

### `TransactionType`

Defines wallet transaction categories:

- `EARN_RECYCLING`
- `REDEEM_REWARD`
- `ADMIN_ADJUST`

### `RewardType`

Defines reward fulfillment type:

- `DIGITAL_VOUCHER`
- `PHYSICAL_PRODUCT`

## User And Profile Models

### `Account`

Stores login and role information.

Important fields:

- `idAccount`: primary key
- `username`: unique username
- `password`: password hash or stored password value
- `email`: unique email
- `role`: one of `UserRole`
- `createdAt`, `updatedAt`: account timestamps

Relationships:

- One account can have one `Customer` profile.
- One account can have one `Driver` profile.
- One account can have one `RecyclingPartner` profile.
- One account can have many `RefreshToken`, `Notification`, and `AuditLog` records.

### `RefreshToken`

Stores hashed refresh tokens for authentication sessions.

Important fields:

- `tokenHash`: unique token hash
- `idAccount`: owner account
- `userAgent`, `ipAddress`: optional session metadata
- `expiresAt`: token expiry

Indexes:

- `idAccount`
- `expiresAt`

Delete behavior:

- Refresh tokens are deleted when their account is deleted.

### `Customer`

Stores customer profile data.

Important fields:

- `fullName`
- `phoneNumber`: unique
- `isEnterprise`: marks whether the customer represents a business
- `idAccount`: unique account link

Relationships:

- One customer belongs to one `Account`.
- One customer can have one `Enterprise`.
- One customer can have many `Address`, `PickupRequest`, and `RewardExchange` records.
- One customer can have one `EcoWallet`.
- One customer can have one `GreenPassport`.

### `Enterprise`

Stores business information for enterprise customers.

Important fields:

- `companyName`
- `taxCode`: unique
- `industry`
- `contactPerson`

Relationship:

- One enterprise belongs to one `Customer`.

### `Driver`

Stores driver profile and current operational data.

Important fields:

- `fullName`
- `phoneNumber`: unique
- `vehicleInfo`
- `licensePlate`
- `isActive`
- `currentLat`, `currentLng`
- `idAccount`: unique account link

Relationships:

- One driver belongs to one `Account`.
- One driver can have many `PickupAssignment` records.
- One driver can own many `CollectionCluster` records.

### `RecyclingPartner`

Stores partner recycler information.

Important fields:

- `name`
- `licenseNumber`: unique
- `address`
- `contactPhone`
- `status`: active/inactive flag
- `idAccount`: unique account link

Relationships:

- One partner belongs to one `Account`.
- One partner can receive many completed or assigned `PickupRequest` records.

## Logistics And Pickup Models

### `Address`

Stores pickup locations for customers.

Important fields:

- `label`: address label such as home, office, or dorm
- `addressLine`
- `ward`
- `district`
- `city`: defaults to `Ho Chi Minh`
- `latitude`, `longitude`
- `isDefault`

Relationships:

- One address belongs to one `Customer`.
- One address can be used by many `PickupRequest` records.

### `PickupRequest`

Represents a recycling pickup order.

Important fields:

- `idCustomer`: requesting customer
- `idAddress`: pickup location
- `idPartner`: optional recycling partner after handoff
- `status`: current pickup status
- `scheduledTime`: requested pickup time
- `totalPoints`: total reward points
- `totalWeight`: total confirmed waste weight
- `note`
- `createdAt`

Relationships:

- One request belongs to one `Customer`.
- One request belongs to one `Address`.
- One request can optionally belong to one `RecyclingPartner`.
- One request has many `WasteItem` records.
- One request has one optional `PickupAssignment`.
- One request has many `PickupTimeline` records.

### `PickupAssignment`

Connects a pickup request to a driver and optionally to a route cluster.

Important fields:

- `idRequest`: unique pickup request link
- `idDriver`: assigned driver
- `idCluster`: optional route cluster
- `routeOrder`: order inside the optimized route
- `assignedAt`

Relationships:

- One assignment belongs to one `PickupRequest`.
- One assignment belongs to one `Driver`.
- One assignment can belong to one `CollectionCluster`.

### `CollectionCluster`

Groups pickup assignments for a driver on a scheduled route.

Important fields:

- `idDriver`: assigned driver
- `scheduledDate`
- `district`
- `status`: text status such as `OPEN`, `IN_PROGRESS`, or `CLOSED`

Relationships:

- One cluster belongs to one `Driver`.
- One cluster has many `PickupAssignment` records.

### `PickupTimeline`

Records status history for a pickup request.

Important fields:

- `idRequest`
- `status`
- `note`
- `createdAt`
- `createdBy`: optional ID of the actor who performed the action

Relationship:

- One timeline entry belongs to one `PickupRequest`.

## Waste Models

### `WasteCategory`

Defines recyclable waste types and their scoring or environmental factors.

Important fields:

- `name`: unique category name
- `co2Factor`: estimated kilograms of CO2 reduced per kilogram of waste
- `pointFactor`: reward points per kilogram
- `hazardLevel`: defaults to `Low`
- `pricePerKg`: optional estimated scrap value
- `iconUrl`

Relationship:

- One category can be used by many `WasteItem` records.

### `WasteItem`

Represents a specific type of waste inside a pickup request.

Important fields:

- `idRequest`
- `idCategory`
- `weight`: confirmed actual weight
- `pointsEarned`

Relationships:

- One item belongs to one `PickupRequest`.
- One item belongs to one `WasteCategory`.
- One item can have many `WasteImage` records.

### `WasteImage`

Stores evidence images for waste items.

Important fields:

- `idItem`
- `url`
- `type`: text value such as `BEFORE_PICKUP` or `AFTER_PICKUP`
- `createdAt`

Relationship:

- One image belongs to one `WasteItem`.

## Rewards And Gamification Models

### `EcoWallet`

Stores a customer's reward point balance.

Important fields:

- `idCustomer`: unique customer link
- `balance`

Relationships:

- One wallet belongs to one `Customer`.
- One wallet has many `Transaction` records.

### `Transaction`

Tracks point changes in an eco wallet.

Important fields:

- `idWallet`
- `type`
- `amount`
- `description`
- `createdAt`

Relationship:

- One transaction belongs to one `EcoWallet`.

### `GreenPassport`

Stores lifetime environmental impact and gamification status.

Important fields:

- `idCustomer`: unique customer link
- `totalKg`
- `totalCO2`
- `totalPoints`
- `level`
- `badge`

Relationship:

- One passport belongs to one `Customer`.

### `Reward`

Defines rewards customers can redeem.

Important fields:

- `name`
- `description`
- `type`
- `pointCost`
- `partnerName`
- `imageUrl`

Relationships:

- One reward can have many `RewardExchange` records.
- One reward can have one `RewardInventory`.

### `RewardInventory`

Tracks inventory for rewards.

Important fields:

- `idReward`: unique reward link
- `stockQuantity`
- `isUnlimited`

Relationships:

- One inventory record belongs to one `Reward`.
- One inventory record can have many `VoucherCode` records.

### `VoucherCode`

Stores digital voucher codes.

Important fields:

- `idInventory`
- `code`: unique
- `isUsed`
- `expiryDate`

Relationship:

- One voucher belongs to one `RewardInventory`.

### `RewardExchange`

Represents a customer redeeming a reward.

Important fields:

- `idCustomer`
- `idReward`
- `createdAt`
- `status`: text value such as `PENDING`, `SUCCESS`, or `FAILED`
- `voucherCodeUsed`

Relationships:

- One exchange belongs to one `Customer`.
- One exchange belongs to one `Reward`.

## Support, Reporting, And Audit Models

### `Notification`

Stores account notifications.

Important fields:

- `idAccount`
- `title`
- `body`
- `isRead`
- `createdAt`

Relationship:

- One notification belongs to one `Account`.

### `ESGReport`

Stores environmental, social, and governance reporting summaries.

Important fields:

- `title`
- `startDate`, `endDate`
- `totalRequests`
- `totalWeight`
- `totalCO2Saved`
- `hazardousWaste`
- `recycledRate`
- `enterpriseId`: optional enterprise reference value
- `createdAt`

Current note:

- `enterpriseId` is stored as a plain optional string and is not currently declared as a Prisma relation to `Enterprise`.

### `AuditLog`

Stores important account actions for traceability.

Important fields:

- `idAccount`
- `action`
- `targetTable`
- `targetId`
- `oldValue`: optional JSON snapshot
- `newValue`: optional JSON snapshot
- `ipAddress`
- `createdAt`

Relationship:

- One audit log belongs to one `Account`.

## Relationship Summary

### Identity

- `Account` to `Customer`: one-to-one optional
- `Account` to `Driver`: one-to-one optional
- `Account` to `RecyclingPartner`: one-to-one optional
- `Account` to `RefreshToken`: one-to-many
- `Account` to `Notification`: one-to-many
- `Account` to `AuditLog`: one-to-many

### Customer Domain

- `Customer` to `Enterprise`: one-to-one optional
- `Customer` to `Address`: one-to-many
- `Customer` to `PickupRequest`: one-to-many
- `Customer` to `EcoWallet`: one-to-one optional
- `Customer` to `GreenPassport`: one-to-one optional
- `Customer` to `RewardExchange`: one-to-many

### Pickup Logistics

- `PickupRequest` to `WasteItem`: one-to-many
- `PickupRequest` to `PickupAssignment`: one-to-one optional
- `PickupRequest` to `PickupTimeline`: one-to-many
- `PickupRequest` to `RecyclingPartner`: many-to-one optional
- `Driver` to `PickupAssignment`: one-to-many
- `Driver` to `CollectionCluster`: one-to-many
- `CollectionCluster` to `PickupAssignment`: one-to-many

### Waste

- `WasteCategory` to `WasteItem`: one-to-many
- `WasteItem` to `WasteImage`: one-to-many

### Rewards

- `EcoWallet` to `Transaction`: one-to-many
- `Reward` to `RewardInventory`: one-to-one optional
- `RewardInventory` to `VoucherCode`: one-to-many
- `Reward` to `RewardExchange`: one-to-many

## Important Constraints

- Unique account identity:
  - `Account.username`
  - `Account.email`
- Unique profile ownership:
  - `Customer.idAccount`
  - `Driver.idAccount`
  - `RecyclingPartner.idAccount`
- Unique contact or business identifiers:
  - `Customer.phoneNumber`
  - `Driver.phoneNumber`
  - `Enterprise.taxCode`
  - `RecyclingPartner.licenseNumber`
- One pickup request can only have one assignment because `PickupAssignment.idRequest` is unique.
- One customer can only have one wallet and one green passport because `EcoWallet.idCustomer` and `GreenPassport.idCustomer` are unique.
- One reward can only have one inventory record because `RewardInventory.idReward` is unique.
- Voucher codes are globally unique through `VoucherCode.code`.

## Design Notes

- Several status-like fields are plain strings instead of enums:
  - `CollectionCluster.status`
  - `WasteImage.type`
  - `RewardExchange.status`
- `ESGReport.enterpriseId` is not enforced by a relation.
- Most relations do not define explicit `onDelete` behavior, so Prisma and the database default relation behavior will apply.
- `RefreshToken` is the only model with explicit cascade delete from `Account`.
